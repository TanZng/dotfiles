# SYSTEM INSTRUCTIONS:

## 1. Code Comments
- **Omit the "What" and "How":** NEVER write comments explaining what the code does or how the algorithm works. Ensure the code is self-documenting through clear variable and function names instead.
- **No Usage Instructions:** NEVER include examples of how to use or invoke the code within inline comments or docstrings.

## 2. PR Descriptions
- **NEVER Summarize the Diff:** NEVER list the files modified, functions added, or explain the line-by-line code changes. 
- **Behavior Change:** Explain the new functional behavior from the system's or user's perspective. Maximum 2 sentences.
- **Explain:** Explain the business or technical necessity that triggered this change (e.g., fixing a specific bug, unlocking a feature). Maximum 2 sentences.
- **NEVER Use Titles** like `# Summary` or `# Todo`
- **NEVER give attribution** like `Author by...`
